# ForeverArmory 0.2.0

Installation, commands, cache behavior, supported collectors and client limitations are documented in the packaged [addon README](../addon/ForeverArmory/README.md) and [changelog](../addon/ForeverArmory/CHANGELOG.md).

The package is generated by `python3 scripts/package.py` as `site/downloads/ForeverArmory.zip` with one top-level ForeverArmory folder. GitHub Pages packages it from the committed addon sources. It retains the existing version-1 importer envelope and adds schemaVersion/addonVersion metadata.

Validation: `npm test`, `npm run test:security`, and `python3 tests/addon-smoke.py /tmp/forever-addon-test.json` after installing test-only `lupa==2.8`; then `node scripts/verify-addon-export.mjs /tmp/forever-addon-test.json`. CI runs the same Lua-generated export round trip. Mocks cover bank open/close/empty/error, missing APIs, GUID isolation, recipe cache timestamps, SavedVariables serialization and legacy/modern tuple handling. The supplied older website backup also passed the current validator.

Real-client acceptance is still required. The complete raw export from the separate conversation was not retrievable; testing uses the supplied backup, the handoff's representative Lasmus values and actual Lua-generated mocked exports. None is mislabeled as a complete original raw capture.

API signatures were inspected in the Blizzard UI source mirror Gethe/wow-ui-source, UnitDocumentation.lua, TradeSkillUIDocumentation.lua and TradeSkillUITypesDocumentation.lua. This guides guarded adapters but does not establish Forever client availability. The pre-existing modern trait/containers branch and Interface 16001/camelot target were preserved.
