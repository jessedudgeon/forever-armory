# ForeverArmory 0.3.0 session exports

Extends released 0.2.0. See the packaged [README](../addon/ForeverArmory/README.md) for installation, exact character SavedVariables path and acceptance steps. No website account credentials or network bridge are included.

Normal logout, exit or `/reload` captures a version-1 JSON payload in per-character `ForeverArmorySessionExport`. The client writes it during its normal SavedVariables save lifecycle. The latest session snapshot replaces the previous snapshot; cumulative confirmed turn-ins remain in `ForeverArmoryJournal`, keyed by realm + GUID/name fallback. `/farmory last` opens the exact saved JSON. `/farmory export` still captures the current character immediately.

The new `Sessions.lua` module registers events defensively. It records only confirmed `QUEST_TURNED_IN` notifications, never quest-log disappearance or an attempted reward click. Quest names are observed through the readable quest log or title API. It doesn't claim historical timestamps for completed-ID backfill. Wire exports contain the latest 2000 events, all known completed IDs and explicit coverage/truncation metadata; older events remain in the local journal. The previous session export survives capture errors or the existing 1 MB JSON limit.

The website accepts JSON and the character SavedVariables `.lua` file. `session-import.js` decodes one explicitly named quoted Lua string without evaluating Lua, supports common string/decimal byte escapes and rejects ambiguous/truncated exports. It imports only the JSON, excluding the remaining SavedVariables. The upload accepts 20 MB of SavedVariables; the extracted JSON must satisfy the original 1 MB boundary. Confirm account and character in the usual review before writing anything. Quest histories merge by event ID, including repeatable turn-ins, and known completed IDs form an additive set. The Progress view shows the latest 50 timed turn-ins and total known completions; backups preserve all imported records.

Validation completed: 97 Node tests; Lua 5.1 mocked execution including modern/missing APIs, bank cache regression checks, session lifecycle, duplicate events, repeated quests, reload recovery, missing titles, failed logout retention, unavailable event registration, wire truncation and character isolation. Actual Lua-generated JSON and Lua SavedVariables both survive website parse, snapshot deduplication, backup and cloud round trips. The owner's September 29 backup validates and importing a generated session preserves all prior snapshots. A browser acceptance script was added for saved-file review/import, escaped quest names, the journal and mobile layout. It could not run here because Chromium is absent and the browser download returned truncated archives; those UI checks remain pending. No real Forever client was available; in-game event availability and disk-write acceptance remain to be confirmed by the owner.

No Firebase rules/schema collections were changed. Existing owner-private character snapshot records and chunking handle the additive fields.
